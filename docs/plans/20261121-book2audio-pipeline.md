# book2audio: пайплайн PDF → русская аудиокнига на Go

## Overview

- `book2audio` — CLI-утилита на Go, которая одной командой превращает PDF в русскую аудиокнигу по главам: извлечение текста → OCR для сканов → очистка → главы → перевод на русский → синтез речи → сборка M4B/MP3.
- Назначение: тексты, на которые у пользователя есть права, — собственные документы и книги в общественном достоянии.
- Проблема: ручная цепочка «PDF → текст → перевод → озвучка» долгая, не возобновляется после сбоя и не даёт править промежуточный результат.
- Ключевые свойства:
  - возобновление после сбоя без повторной работы над готовыми единицами;
  - промежуточный текст (границы глав, текст глав, перевод, глоссарий) можно править руками; ручные правки не затираются, пересчитывается только зависящее от них;
  - бэкенды перевода и озвучки сменные: Go-интерфейсы `Translator` и `Synthesizer`, в первой версии по одной реализации.

### Критерии приёмки

1. `book2audio run book.pdf` создаёт `work/<slug>/out/<slug>.m4b` с оглавлением по главам и русский текст каждой главы.
2. Прерванный запуск (в том числе аварийно) продолжается с места остановки; готовые единицы не пересчитываются.
3. Правка пересчитывает только зависящее от неё:
   - правка текста главы — фрагменты перевода от места правки до конца этой главы; фрагменты с прежним содержимым берутся из кэша, другие главы не затрагиваются;
   - правка перевода главы — только сегменты озвучки изменённых абзацев;
   - правка глоссария — только фрагменты, в которых встречается изменённый термин.
4. Файл, изменённый вручную, не перезаписывается без `--force`.
5. Страницы PDF без текстового слоя распознаются через OCR.
6. Смена бэкенда перевода или озвучки делается в конфиге книги, без правок кода пайплайна.

## Solution Overview

Выбран вариант **«этапы с рабочей папкой на диске»**.

- Пайплайн — последовательность этапов: `extract → chapters → translate → synth → build`. Каждый этап читает файлы предыдущего и пишет свои в `work/<slug>/`.
- Состояние хранится в `manifest.json`: для каждой единицы работы — хэш входа, путь результата, хэш записанного результата, статус.
- Внутри этапа единицы обрабатываются пулом воркеров; между этапами параллелизма нет.
- Команды CLI: `init`, `extract`, `chapters`, `translate`, `synth`, `build`, `run` (все этапы подряд), `status`.

Ключевые решения:

- **Файлы, а не БД**: промежуточный текст правится обычным редактором; отладка — просмотром папки.
- **Результаты перевода и озвучки адресуются по содержимому**: файл кэша называется хэшем входа (`cache/<хэш>.ru.txt`, `cache/<хэш>.wav`), а порядок фрагментов главы хранится отдельным списком хэшей. Сдвиг номеров при вставке или удалении абзаца ничего не пересчитывает.
- **Фрагмент перевода** собирается из целых абзацев до `chunk_chars`. После правки главы границы фрагментов ниже места правки могут сдвинуться, поэтому пересчёт идёт до конца главы (см. критерий 3). «Плавающие» якорные границы не вводятся — лишняя сложность для первой версии.
- **Сегмент озвучки не выходит за границу абзаца**: правка абзаца перевода пересчитывает только его сегменты.
- **Единое правило ручных правок**: манифест хранит `out_sha256` каждого записанного редактируемого файла. Если текущий хэш файла отличается — файл правили руками: он не перезаписывается, считается источником истины, выводится предупреждение; принудительная перезапись — `--force`.
- **Перевод — OpenAI-совместимый HTTP** (`/chat/completions`): одна реализация покрывает и локальные серверы (Ollama, llama.cpp, vLLM), и облачные API; выбор — через `base_url`.
- **Озвучка — Piper через подпроцесс**: локально, без оплаты за символы. Команда и аргументы задаются в конфиге, потому что CLI разных выпусков Piper отличается.
- **Склейка аудио — в Go**: PCM сегментов и паузы склеиваются кодом, длительности считаются точно по числу сэмплов; `ffmpeg` нужен только для кодирования.
- **Бэкенд выбирается простой фабрикой** (`switch cfg.Backend`), без реестра.
- **Ошибка единицы не роняет этап**: единица помечается `failed` с текстом ошибки, остальные продолжаются, этап завершается с ненулевым кодом; `run` не переходит к следующему этапу при наличии `failed`.

## Technical Details

### Контракт CLI

```
book2audio init <book.pdf> [--config cfg.yaml] [--workdir work] [--slug name]
book2audio <extract|chapters|translate|synth|build|status> <book.pdf | work/<slug>>
book2audio run <book.pdf | work/<slug>> [--from stage] [--to stage]
общие флаги: --force, -v
```

- Аргумент-PDF разрешается в `work/<slug>`; sha256 файла сверяется с манифестом, при расхождении — ошибка.
- slug строится из имени файла: нижний регистр, буквы и цифры любого алфавита сохраняются, остальное заменяется на `-`. Если папка с таким slug принадлежит другому PDF — ошибка с подсказкой про `--slug`.
- `init` копирует конфиг в `work/<slug>/config.yaml`; после этого главный конфиг книги — именно он. `--config` при последующих командах заменяет его на один запуск.
- `run` для PDF без рабочей папки сам выполняет `init`.
- На время любой команды берётся эксклюзивная блокировка `work/<slug>/.lock`; второй запуск завершается с понятной ошибкой.

### Рабочая папка

Знаком ✎ отмечены файлы, которые можно править руками; остальные — производные.

```
work/<slug>/
  .lock
  manifest.json
  config.yaml                          # главный конфиг книги
  glossary.yaml                      ✎ # термины и имена: source → target
  01-pages/p0001.txt …                 # сырой текст по страницам
  02-chapters/chapters.json          ✎ # начало каждой главы
  02-chapters/ch01.md …              ✎ # очищенный текст главы: "# Заголовок" + абзацы
  03-translated/cache/<хэш>.ru.txt     # переводы фрагментов
  03-translated/ch01.chunks.json       # порядок фрагментов главы (список хэшей)
  03-translated/ch01.ru.md           ✎ # собранная глава на русском
  04-audio/cache/<хэш>.wav             # сегменты озвучки
  04-audio/ch01.segments.json          # порядок сегментов и пометки конца абзаца
  04-audio/ch01.wav                    # склеенная глава
  out/<slug>.m4b | out/NN-<заголовок>.mp3
```

- Перевод правится в `chNN.ru.md`; после правки файл больше не пересобирается из фрагментов (до `--force`).
- Файлы кэша не удаляются: при откате правки результат берётся из кэша без повторной работы.
- Результат, положенный вручную по пути, который показывает `status` для `failed`-единицы, принимается как готовый.

### chapters.json

```json
[
  {"n": 0, "title": "Вступление", "start_page": 1,  "start_line": 1},
  {"n": 1, "title": "Chapter 1",  "start_page": 9,  "start_line": 14}
]
```

- начало главы задано страницей и номером строки в `01-pages/pNNNN.txt`; глава заканчивается там, где начинается следующая;
- текст до первого найденного заголовка — глава 0.

### Манифест

```json
{
  "version": 1,
  "source": {"path": "book.pdf", "sha256": "…", "pages": 300,
             "title": "…", "author": "…"},
  "stages": {
    "extract": {"units": {
      "p0007": {"in": "…", "out": "01-pages/p0007.txt", "out_sha256": "…",
                "status": "done", "ocr": true}}},
    "translate": {"units": {
      "<хэш входа>": {"out": "03-translated/cache/<хэш>.ru.txt",
                      "status": "failed", "error": "…", "chapter": "ch01"}}}
  }
}
```

- статусы: `pending`, `done`, `failed`;
- единица пропускается, если статус `done`, файл результата существует и хэш входа не изменился;
- запись после каждой единицы: под мьютексом, временный файл → `fsync` → `rename`;
- в конце этапа из манифеста удаляются единицы, которых нет в текущем составе работ.

### Что входит в хэш входа

| Этап | Единица | Хэш входа |
|---|---|---|
| extract | страница | sha256 PDF + номер страницы + `ocr_min_chars`, `ocr_lang`, `ocr_dpi` |
| chapters | глава | хэши страниц главы + её границы + версия правил очистки |
| translate | фрагмент | текст фрагмента + встречающиеся термины глоссария + бэкенд, модель, языки, температура + хэш шаблона промпта |
| synth | сегмент | текст сегмента + бэкенд, `command`, `args` (до подстановки `{out}`) |
| build | WAV главы | список хэшей сегментов по порядку + `paragraph_pause_ms` |
| build | итоговый файл | хэши WAV глав + `format`, `bitrate`, заголовки глав, теги книги |

Контекст (хвост предыдущего фрагмента) в хэш перевода не входит.

### Конфиг (пример)

```yaml
source_lang: en
target_lang: ru
workdir: work
book:                      # необязательно; по умолчанию из pdfinfo
  title: ""
  author: ""
extract:
  ocr_min_chars: 50        # страница короче — в OCR
  ocr_lang: ""             # код tesseract; пусто — выводится из source_lang (en → eng)
  ocr_dpi: 300
  ocr_workers: 4
chapters:
  heading_regex: '^(Chapter|Part|Глава|Часть)\s+\S+'
  heading_max_chars: 80    # заголовок — отдельная короткая строка
  toc_max_headings: 3      # страница с большим числом совпадений считается оглавлением
  fallback_pages: 20       # если заголовки не найдены
translate:
  backend: openai
  base_url: http://localhost:11434/v1
  model: "<имя модели>"
  api_key_env: B2A_API_KEY
  temperature: 0.2
  chunk_chars: 3500
  workers: 4
  max_retries: 5           # только транспортные сбои: 429, 5xx, таймаут
tts:
  backend: piper
  command: piper
  args: ["--model", "voices/ru_RU-irina-medium.onnx", "--output_file", "{out}"]
  segment_chars: 1200      # абзац длиннее делится по предложениям
  workers: 2
audio:
  format: m4b              # m4b | mp3
  bitrate: 64k
  paragraph_pause_ms: 400
```

### Интерфейсы

```go
// internal/translate
type Request struct {
    Text        string
    SourceLang  string
    TargetLang  string
    Glossary    []Term // только термины, встречающиеся в Text
    PrevContext string // хвост предыдущего фрагмента, в хэш не входит
}
type Translator interface {
    Translate(ctx context.Context, req Request) (string, error)
}
func New(cfg config.Translate) (Translator, error) // switch cfg.Backend

// internal/tts
type Synthesizer interface {
    // Synthesize пишет PCM-WAV с озвучкой text в файл outPath.
    Synthesize(ctx context.Context, text, outPath string) error
}
func New(cfg config.TTS, r execx.Runner) (Synthesizer, error) // switch cfg.Backend

// internal/execx
type Cmd struct {
    Name  string
    Args  []string
    Env   []string  // добавляется к окружению процесса
    Stdin io.Reader
}
type Runner interface {
    Run(ctx context.Context, cmd Cmd) (stdout []byte, err error)
}
```

### Поток обработки

1. **extract**: `pdfinfo` → число страниц, название, автор; `pdftotext <pdf> -` один раз, разбиение по `\f` с отбрасыванием пустого хвоста; страница короче `ocr_min_chars` → `pdftoppm -r <dpi> -png -singlefile -f N -l N` + `tesseract <png> stdout -l <lang>` с `OMP_THREAD_LIMIT=1`.
2. **chapters**:
   1. построчная очистка страниц: колонтитулы, номера страниц;
   2. поиск заголовков по строкам — до склейки в абзацы; заголовок — отдельная строка не длиннее `heading_max_chars`; страницы с числом совпадений больше `toc_max_headings` пропускаются как оглавление;
   3. запись `chapters.json` (если он изменён вручную — границы берутся из него);
   4. сборка абзацев внутри главы: снятие переносов, склейка строк и абзацев, разорванных границей страницы → `chNN.md`.
3. **translate**: глава режется на фрагменты из целых абзацев до `chunk_chars` (абзац длиннее лимита — по предложениям) → перевод воркерами → проверка результата (не пусто, отношение длин в допустимых пределах) → `chNN.chunks.json` → сборка `chNN.ru.md`.
   - повторы: HTTP-клиент повторяет только транспортные сбои; этап делает ровно одну повторную попытку при непрошедшей проверке, затем `failed`.
4. **synth**: из `chNN.ru.md` — снятие разметки, сносок, URL → сегмент = абзац (длинный абзац делится по предложениям), заголовок главы — отдельный сегмент; переводы строк внутри сегмента заменяются пробелами → WAV на сегмент → `chNN.segments.json`.
5. **build**: склейка PCM сегментов главы в Go со вставкой тишины между абзацами и проверкой одинакового формата (частота, каналы, разрядность) → длительности глав по числу сэмплов → кодирование:
   - `m4b`: PCM глав подаётся в `ffmpeg` потоком через stdin (`-f s16le -ar <частота> -ac <каналы> -i pipe:0 -i <ffmetadata> -map_metadata 1 -map_chapters 1 -c:a aac -b:a <bitrate>`), главы — блоки `[CHAPTER]` в файле `FFMETADATA`;
   - `mp3`: файл на главу (`libmp3lame`), теги `title` и `track`;
   - заголовки глав берутся из строки `# ` в `chNN.ru.md`, теги книги — из конфига или `pdfinfo`.

### Параллелизм

- пул воркеров — общий помощник `workpool.Run(ctx, n, items, fn)` на стандартной библиотеке (`sync.WaitGroup.Go` и канал-семафор на `n` мест);
- сбой единицы — `MarkFailed` без остановки остальных; фатальная ошибка (отмена контекста, сбой записи манифеста) отменяет контекст этапа и возвращается из `Run`;
- обработка SIGINT/SIGTERM — `signal.NotifyContext` в `main`, действует для всех подкоманд.
